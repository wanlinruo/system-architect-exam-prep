## 三、各节内容设计

### 5.1 测试基础（了解）

**核心内容**：
- 测试目的（发现错误、评估质量、验证需求）
- 测试原则（穷举不可能 / 早测试早发现 / Pareto 80-20 / 第三方测试更客观）
- V&V 区分：
  - 验证（Verification）：是否正确做产品（符合规格）
  - 确认（Validation）：是否做正确产品（符合用户需求）
- 调试 vs 测试 对比表

**关键 callout**：
- `> [!important]` V&V 一句话区分口诀
- `> [!tip]` 调试 vs 测试 5 维度对比

### 5.2 测试方法（重点★★★★）

**核心内容**：
- **按是否执行代码**：
  - 静态测试：代码审查、走查、桌面检查
  - 动态测试：实际执行程序，输入测试用例
- **按是否需要代码细节**：
  - 黑盒（功能/数据驱动测试）：不看代码，只看输入输出
  - 白盒（结构/逻辑驱动测试）：需要代码，覆盖路径/分支
  - 灰盒：介于两者，部分了解内部结构

**黑盒 vs 白盒 vs 灰盒 对比表**（维度：是否需要代码 / 关注点 / 测试人员 / 适用阶段 / 优缺点）

**关键 callout**：
- `> [!important]` 三种测试对比表
- `> [!warning]` 易混点：黑盒不是不知道任何东西，是不需要看代码内部

### 5.3 黑盒测试用例设计（重点★★★★）

**核心内容**：
- **等价类划分**：
  - 有效等价类（合法输入）/ 无效等价类（非法输入）
  - 设计原则：每个有效类至少 1 用例覆盖；每个无效类单独 1 用例
- **边界值分析**：
  - 取值原则：刚好等于 / 刚好大于 / 刚好小于（≤0、=0、>0、=max-1、=max、>max）
  - 与等价类配合使用，效果加倍
- **决策表（判定表）**：
  - 4 部分：条件桩、动作桩、条件项、动作项
  - 适用：业务规则复杂、条件组合多
- **因果图**：找输入输出之间的因果关系
- **错误推测**：基于经验列举可能错误
- **场景法**：基于用例的基本流和备选流

**考试示例**：年龄输入字段（1-150）的等价类与边界值用例设计

**关键 callout**：
- `> [!important]` 等价类 + 边界值 是黑盒最常用组合
- `> [!tip]` 边界值取值套路（≤、=、>×3 个边界）

### 5.4 白盒测试用例设计（重点★★★★）

**核心内容**：
- **6 种覆盖准则强弱顺序**（自弱到强）：
  1. 语句覆盖（SC）— 每条语句执行一次
  2. 判定覆盖（DC，分支覆盖）— 每个判定的真/假分支至少执行一次
  3. 条件覆盖（CC）— 每个判定中每个条件的真/假至少执行一次
  4. 判定/条件覆盖（DCC）— 同时满足判定与条件
  5. 条件组合覆盖（MCC）— 每个判定中条件的所有组合都执行
  6. 路径覆盖（PC）— 程序所有可能路径都执行
- **覆盖强度排序**：路径 > 条件组合 > 判定/条件 > 条件 ≈ 判定 > 语句
- **关键易混点**：
  - 满足条件覆盖不一定满足判定覆盖（例：条件 A、B，A=T B=F → 判定 F；A=F B=T → 判定 F；条件覆盖满足但判定的"真"分支没覆盖）
- **McCabe 环路复杂度**：引用 [[12-系统可靠性#McCabe环路复杂度]]，不重复推导

**考试示例**：if (A && B) 代码片段，分别给出语句/判定/条件/判定条件/条件组合 5 种覆盖的最少测试用例集

**关键 callout**：
- `> [!important]` 6 种覆盖强弱排序
- `> [!warning]` 条件覆盖 ⊄ 判定覆盖（经典易混点）
- `> [!note]` McCabe 环路复杂度参见 [[12-系统可靠性]]

### 5.5 测试阶段（次重点★★★）

**核心内容**：
- **5 大阶段顺序**（V 模型对应）：
  1. **单元测试**：模块内部，由开发人员执行，依据详细设计，使用桩 stub / 驱动 driver
  2. **集成测试**：模块间接口，依据概要设计
  3. **系统测试**：完整系统，依据需求规格，黑盒为主
  4. **验收测试**：用户参与，依据用户需求，α / β 测试
  5. **回归测试**：贯穿所有阶段，确保修改不引入新错误

- **三种集成策略**对比：
  - **自顶向下**（深度优先 / 广度优先）— 需要桩模块 stub
  - **自底向上**— 需要驱动模块 driver
  - **大爆炸**（一次性集成）— 不推荐，故障定位难

**关键 callout**：
- `> [!important]` 测试阶段对照表（阶段 / 依据 / 主要执行人 / 测试类型）
- `> [!warning]` 易混点：桩 stub（顶向下用，模拟下层）vs 驱动 driver（底向上用，模拟上层）
- `> [!tip]` α 测试在开发现场，β 测试在用户现场

### 5.6 系统测试类型（次重点★★★）

**核心内容**：
- **性能测试**：在指定条件下系统的响应时间、吞吐量等指标
- **负载测试**：逐步增加负载，找出系统的极限和瓶颈
- **压力测试**：超出正常负载下系统的稳定性，看系统是否崩溃
- **容量测试**：找系统能处理的最大数据/用户/连接数
- **可用性测试**：用户操作的方便程度
- **安全性测试**：抵御非法访问、防止数据泄露
- **兼容性测试**：跨平台、跨浏览器、跨版本
- **恢复测试**：故障后系统能否恢复到正常状态
- **可靠性测试**：长时间运行下系统的稳定性（MTBF）
- **配置测试**：不同硬件/软件配置下的行为

**关键 callout**：
- `> [!important]` 性能 / 负载 / 压力 / 容量 四者区分（最常考易混点）
- `> [!tip]` 题目区分技巧：看到"找极限/瓶颈" → 负载；"超极限稳定性" → 压力；"最大处理量" → 容量
