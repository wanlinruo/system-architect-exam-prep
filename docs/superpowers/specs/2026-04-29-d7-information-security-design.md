## 三、各节内容设计

### 13.1 信息安全基础（了解）

**核心内容**：
- **信息安全 CIA 三要素**：
    - **机密性**（Confidentiality）：信息不被非授权者获取
    - **完整性**（Integrity）：信息不被非授权篡改
    - **可用性**（Availability）：信息能被授权用户使用
- **扩展三属性**：真实性 / 可控性 / 不可否认性
- **信息安全 5 层次**：设备安全 / 数据安全 / 内容安全 / 行为安全 / 关系安全（系统级层次）
- **安全管理（CIA 之外）**：物理安全、人员安全、规章制度

**关键 callout**：
- `> [!important]` CIA 三要素 — 最常考的考点之一
- `> [!tip]` 三要素口诀：**机完用**（机密性、完整性、可用性）

### 13.2 加密技术（重点★★★★★）

**核心内容**：

**对称加密 vs 非对称加密对比（必考）**：

| 维度 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 别名 | 私钥加密 / 共享密钥 | 公钥加密 |
| 密钥数量 | 双方 ==同一把密钥== | 一对密钥（公钥 + 私钥） |
| 加密速度 | **快** | 慢（约 1000 倍差距） |
| 密钥管理 | 难（n 个用户 n(n-1)/2 把密钥） | 易（n 个用户共 2n 把密钥） |
| 适用场景 | 大数据量加密 | 密钥交换、数字签名 |
| 典型算法 | DES / 3DES / AES / IDEA / RC4 / SM4 | RSA / ECC / DSA / DH / ElGamal / SM2 |

**主流对称算法表**：
- DES：56-bit 密钥（已不安全）
- 3DES：3 次 DES，等效 168-bit
- AES：128/192/256-bit（主流）
- IDEA：128-bit
- RC4：流密码
- SM4：国密对称，128-bit

**主流非对称算法表**：
- RSA：基于大整数因式分解
- ECC：基于椭圆曲线（同等强度密钥更短）
- DH（Diffie-Hellman）：密钥交换
- DSA：仅用于签名
- SM2：国密非对称，基于 ECC

**哈希算法对比**：
- MD5：==128-bit== 摘要（已不安全）
- SHA-1：==160-bit== 摘要
- SHA-256：256-bit 摘要
- SM3：国密哈希，256-bit

**数字信封原理（速度 + 安全兼顾）**：
- 用对称密钥加密大数据
- 用非对称（接收方公钥）加密对称密钥
- 接收方用私钥解出对称密钥再解数据

**关键 callout**：
- `> [!important]` 对称 vs 非对称 对比表（必考）
- `> [!important]` 主流算法分类记忆
- `> [!warning]` 易混点：DH 是密钥交换非加密；DSA 仅签名不加密
- `> [!tip]` 数字信封 = 非对称传密钥 + 对称加数据
- `> [!warning]` MD5/SHA-1 已被破解，仅做识别用，不能用于安全场景

### 13.3 认证与数字签名（重点★★★★）

**核心内容**：

**数字签名原理（必考）**：

==发送方用 **私钥** 加密 → 签名；接收方用 **公钥** 解密 → 验证==

具体流程：
1. 发送方对原文做哈希得到摘要
2. 发送方用 ==自己的私钥== 加密摘要 → 签名
3. 发送方将原文 + 签名一起发给接收方
4. 接收方用 ==发送方公钥== 解密签名得到摘要 1
5. 接收方对原文做哈希得到摘要 2
6. 比对摘要 1 与摘要 2，一致则认证通过

**数字签名作用**（4 个）：
- **认证**（确认发送方身份）
- **完整性**（消息未被篡改）
- **不可否认**（发送方不能抵赖）
- ==不提供保密性==（如需保密，结合数字信封）

**数字证书（X.509 标准）**：包含公钥、CA 签名、证书有效期、证书主体信息

**PKI（公钥基础设施）**：CA（证书颁发机构）+ RA（注册机构）+ 仓库 + 用户

**Kerberos 认证**：基于对称密钥的网络认证协议，使用 KDC（密钥分发中心）

**关键 callout**：
- `> [!important]` 数字签名口诀：==**发送方私钥签、接收方公钥验**==
- `> [!warning]` 易混：数字签名 ≠ 数字证书；数字签名不提供保密性
- `> [!tip]` 加密用对方公钥（保密性）；签名用自己私钥（不可否认性）

### 13.4 网络安全协议（重点★★★★）

**核心内容**：

**各层网络安全协议归属表（必考）**：

| OSI 层级 | TCP/IP 层级 | 安全协议 | 用途 |
|---------|------------|---------|------|
| **应用层** | 应用层 | **PGP**（邮件加密签名） | 电子邮件 |
| 应用层 | 应用层 | **S/MIME**（安全邮件） | 电子邮件 |
| 应用层 | 应用层 | **HTTPS** = HTTP + SSL/TLS | Web 加密 |
| 应用层 | 应用层 | **SSH**（安全外壳） | 远程登录 |
| **传输层** | 传输层 | **SSL / TLS**（安全套接字） | 通用加密 |
| **网络层** | 网际层 | **IPSec**（IP 安全） | VPN / 站点对站点 |
| **数据链路层** | 网络接口层 | **PPTP / L2TP** | 拨号 / 隧道 VPN |

**SSL / TLS 详解**：
- 工作在 TCP 之上、应用层之下
- 三大功能：身份认证（证书）+ 数据加密（对称）+ 完整性（哈希）
- 握手过程使用非对称交换对称密钥（数字信封思想）

**IPSec**：
- 两种模式：**传输模式**（端到端、加密 payload）/ **隧道模式**（网关到网关、加密整个 IP 包）
- 两种协议：**AH**（认证头，提供完整性）/ **ESP**（封装安全 payload，提供加密 + 完整性）

**关键 callout**：
- `> [!important]` 各层安全协议归属（必考速记表）
- `> [!tip]` 速记：应用层 PGP/HTTPS/SSH，传输层 SSL/TLS，网络层 IPSec，链路层 PPTP/L2TP
- `> [!warning]` SSL 在传输层之上、应用层之下（独立的 SSL 子层）

### 13.5 安全模型（次重点★★★）

**核心内容**：

**3 大安全模型对比（必考）**：

| 模型 | 关注属性 | 核心规则 | 常考口诀 |
|------|---------|---------|---------|
| **BLP**（Bell-LaPadula） | **机密性** | 不上读、不下写（向下读、向上写） | "向下读、向上写"（防泄密） |
| **Biba** | **完整性** | 不下读、不上写（向上读、向下写） | "向上读、向下写"（防污染） |
| **Chinese Wall**（中国墙） | **利益冲突** | 同一冲突类内，已访问 A 后不能再访问 B | 商业伦理、咨询行业 |

**BLP 详解**：
- ==简单安全特性==（ss 特性）：主体不能读取比自身安全级别高的客体（不上读 / no read up）
- ==星特性==（* 特性）：主体不能写入比自身安全级别低的客体（不下写 / no write down）
- 整体效果：信息只能从低密级流向高密级

**Biba 详解**：
- ==简单完整性==：主体不能读取比自身完整级别低的客体（不下读 / no read down）
- ==完整性 *==：主体不能写入比自身完整级别高的客体（不上写 / no write up）
- 与 BLP 镜像对称

**关键 callout**：
- `> [!important]` BLP（机密性）vs Biba（完整性）对照
- `> [!warning]` 易混：BLP 不上读、Biba 不下读；BLP 防泄密、Biba 防污染
- `> [!tip]` 速记：BLP 像保密文件（高级低级别看不到），Biba 像水源（不喝下游、不污上游）

### 13.6 等级保护（了解）

**核心内容**：

**等保 2.0 五级**：

| 级别 | 名称 | 受到破坏后影响 | 适用对象 |
|------|------|--------------|---------|
| 第一级 | 用户自主保护级 | 损害公民、法人、其他组织 | 一般信息系统 |
| 第二级 | 系统审计保护级 | 严重损害公民、法人；轻微损害社会秩序、公共利益 | 一般行政事务 |
| 第三级 | 安全标记保护级 | 严重损害社会秩序公共利益、损害国家安全 | ==政府系统、银行核心、医疗等== |
| 第四级 | 结构化保护级 | 特别严重损害社会秩序公共利益、严重损害国家安全 | 重要金融、电信、能源 |
| 第五级 | 访问验证保护级 | 特别严重损害国家安全 | 极少数核心要害系统 |

**关键 callout**：
- `> [!note]` 等保 2.0 = 等保 1.0 + 云 / 移动 / 物联网 / 工控扩展要求

### 13.7 安全攻击类型（次重点★★★）

**核心内容**：

**常见攻击对比表**：

| 攻击类型 | 全称 | 工作原理 | 防御措施 |
|---------|------|---------|---------|
| **DoS** | Denial of Service | 大量请求耗尽资源 | 限流、防火墙规则 |
| **DDoS** | Distributed DoS | 多台肉鸡同时 DoS | CDN、流量清洗 |
| **SQL 注入** | SQL Injection | 输入恶意 SQL 字符 | 参数化查询、ORM |
| **XSS** | Cross-Site Scripting | 注入恶意 JS 到其他用户浏览器 | 输入过滤、CSP |
| **CSRF** | Cross-Site Request Forgery | 诱使用户在已登录状态发出非预期请求 | Token 验证、Referer 检查 |
| **重放攻击** | Replay Attack | 重发截获的合法请求 | Nonce、时间戳、序列号 |
| **中间人攻击 MITM** | Man-In-The-Middle | 拦截并篡改通信内容 | HTTPS、证书校验 |
| **密码分析** | Cryptanalysis | 暴力破解 / 字典 / 频率分析 | 高强度密钥、加盐哈希 |

**关键 callout**：
- `> [!warning]` XSS 攻击其他用户、CSRF 利用用户当前会话
- `> [!tip]` 防御口诀：注入用参数化、XSS 过滤输入、CSRF 用 Token、MITM 用 HTTPS
