## 三、各节内容设计

### 8.1 项目管理基础（了解）

**核心内容**：
- **项目特征**：临时性、独特性、渐进明细
- **项目集 vs 项目组合 vs 项目** 三层级对比
    - 项目（Project）：单个产出
    - 项目集（Program）：相关项目集合，共同产出战略价值
    - 项目组合（Portfolio）：项目+项目集的总集合，对齐组织战略
- **10 大知识领域**：整合 / 范围 / 进度 / 成本 / 质量 / 资源 / 沟通 / 风险 / 采购 / 相关方
- **5 大过程组**：启动 / 规划 / 执行 / 监控 / 收尾
- **范围管理 — WBS 工作分解结构**：100% 原则、最低层级是工作包

**关键 callout**：
- `> [!important]` 项目集 vs 项目组合 vs 项目 三层级
- `> [!tip]` 10 大知识领域 + 5 大过程组速记

### 8.2 进度管理（重点★★★★）

**核心内容**：

**4 种进度图工具对比**：
- 甘特图（Gantt）：横道图、显示任务时间，==不显示依赖关系==
- 网络图（PDM/单代号网络图）：节点表任务、箭线表依赖
- PERT 图：三点估算、考虑不确定性
- 里程碑图：关键节点

**关键路径法 CPM（必考计算）**：
- 最早开始（ES）/ 最早结束（EF）：==正推==（从起点到终点取最大值）
- 最晚开始（LS）/ 最晚结束（LF）：==反推==（从终点到起点取最小值）
- 总浮动时间 = LS - ES = LF - EF
- 关键路径 = 总工期最长的路径 = 总浮动时间为 0 的路径
- 关键活动：浮动时间 = 0 的活动

**PERT 三点估算（必考公式）**：
- 期望工期 te = (a + 4m + b) / 6
- 标准差 σ = (b - a) / 6
- 方差 V = σ²
- 其中 a = 乐观时间、m = 最可能时间、b = 悲观时间

**关键 callout**：
- `> [!important]` CPM 算法步骤（正推 ES/EF + 反推 LS/LF + 浮动时间）
- `> [!important]` PERT 三点估算公式
- `> [!tip]` CPM 计算示例（5-7 节点网络图 + 完整 ES/EF/LS/LF 表）
- `> [!warning]` 易混点：关键路径可能 ==不止一条==；浮动时间可正可零，但==负数表示进度偏差==

### 8.3 成本管理（重点★★★★）

**核心内容**：

**3 大基础值（EVM 三要素）**：
- **PV（计划价值，Planned Value）**：计划在某时点应完成的工作的预算成本
- **EV（挣值，Earned Value）**：实际完成工作的预算成本（产出价值）
- **AC（实际成本，Actual Cost）**：实际完成工作的实际花费

**4 个偏差/绩效指标**：
- **SV（进度偏差）= EV - PV**：>0 提前、<0 滞后
- **CV（成本偏差）= EV - AC**：>0 节约、<0 超支
- **SPI（进度绩效指数）= EV / PV**：>1 进度好、<1 进度差
- **CPI（成本绩效指数）= EV / AC**：>1 成本好、<1 超支

**关键 callout**：
- `> [!important]` EVM 公式集（必背 5 个公式）
- `> [!tip]` 速记口诀：**E 减 P 是进度（SV/SPI）、E 减 A 是成本（CV/CPI）**；**减号是偏差、除号是指数**
- `> [!warning]` 易混：SV 和 CV 都是 ==EV 在前==（EV - PV / EV - AC）
- `> [!tip]` 计算示例：项目预算 1000、计划完成 60% / 实际完成 50% / 实际花费 600，求 PV、EV、AC、SV、CV、SPI、CPI

### 8.4 质量管理（次重点★★★）

**核心内容**：

**质量管理思想**：
- **戴明 PDCA 循环**（计划 Plan / 执行 Do / 检查 Check / 处理 Act）
- **零缺陷思想**（Crosby）
- **六西格玛（Six Sigma）**：3.4 缺陷/百万机会，DMAIC 流程（定义 / 测量 / 分析 / 改进 / 控制）

**质量管理 7 大经典工具**：
- 因果图（鱼骨图）/ 控制图 / 流程图 / 直方图 / 帕累托图 / 检查表 / 散点图

**关键 callout**：
- `> [!important]` PDCA 循环 + 六西格玛 DMAIC
- `> [!note]` 老七工具 = 因果 / 控制 / 流程 / 直方 / 帕累托 / 检查 / 散点

### 8.5 风险管理（重点★★★★）

**核心内容**：

**风险分类**：
- 按可控性：可管理风险 / 不可管理风险
- 按性质：纯粹风险（只损失）/ 投机风险（可能盈利）

**风险管理过程**（PMBOK 6 步）：
1. 风险管理规划
2. 风险识别
3. 定性风险分析（概率-影响矩阵）
4. 定量风险分析（蒙特卡洛 / 决策树 / EMV 期望货币值）
5. 风险应对计划
6. 风险监控

**风险应对 4 大策略 — 必考**：
- 对负面风险（威胁）：
    - **回避**（Avoid）：消除威胁
    - **转移**（Transfer）：转给第三方（保险、外包）
    - **减轻**（Mitigate）：降低概率/影响
    - **接受**（Accept）：被动/主动接受
- 对正面风险（机会）：开拓 / 分享 / 提高 / 接受

**EMV 期望货币值**：EMV = 概率 × 后果价值

**关键 callout**：
- `> [!important]` 风险应对 4 大策略（负面）
- `> [!tip]` 关键字判定：投保险 → 转移；放弃方案 → 回避；增加冗余 → 减轻；不处理 → 接受
- `> [!note]` 定量分析方法：蒙特卡洛模拟、决策树、EMV

### 8.6 软件配置管理（次重点★★★）

**核心内容**：

**核心概念**：
- **配置项（CI）**：受 SCM 控制的软件元素（代码、文档、计划等）
- **基线（Baseline）**：经过正式审查批准的配置项集合，==是变更的基准==
- 三大基线：功能基线 / 分配基线 / 产品基线

**版本号惯例**：
- **A.B.C** 三段式：主版本 . 次版本 . 修订
- 主版本变更：架构级重大变化
- 次版本变更：新增功能
- 修订变更：bug 修复

**变更控制委员会 CCB（Change Control Board）**：
- 由项目相关方组成
- 评审、批准、拒绝变更请求
- ==基线一旦确定，必须经 CCB 批准才能变更==

**SCM 主要活动**：标识、版本控制、变更控制、配置审计、状态报告

**关键 callout**：
- `> [!important]` 基线 = 受控起点；CCB 批准方可变更
- `> [!warning]` 易混：配置项 ⊃ 基线（基线是配置项的子集 + 经过审批）

### 8.7 沟通管理（次重点★★★）

**核心内容**：

**沟通渠道公式（必考）**：
- **沟通渠道数 = n(n-1)/2**（n = 项目相关方人数）
- 例：5 人项目 → 5×4/2 = 10 条沟通渠道
- 例：10 人项目 → 10×9/2 = 45 条
- 例：增加第 n 个人，新增 n-1 条渠道

**沟通方式**：
- 正式 vs 非正式
- 书面 vs 口头
- 内部 vs 外部
- 上行 / 下行 / 横向

**沟通模型**：发送者 → 编码 → 介质 → 解码 → 接收者，含噪声与反馈

**关键 callout**：
- `> [!important]` 沟通渠道公式 n(n-1)/2 + 计算示例
- `> [!tip]` 题目套路：n 人、n-1 人变化时新增/减少多少条
